# 바구니 유니버스 — 직군 확장 스토리 바이블 (초안 v0.1)

`docs/storyboard/00-bible.md`(= `STORYBOARD.md`의 0장)는 **Data Engineering A to Z 한 편**의 규칙이다. 이 문서는 그 위에 얹는 **상위 바이블**이다. 쇼핑몰 '바구니' 안의 여러 직군이 각자 주인공이 되는 트랙을 만들 때, 서로 어긋나지 않게 하는 규칙과 연표를 정한다.

> 상태: **초안**. `[초안]` 표시는 새로 지어낸 설정이라 확정이 필요하다. 표시 없는 사건·숫자·대사는 이미 데이터 엔지니어링(DE)편에 있는 **정본**이다.

---

## 0. 한눈에 보기

- **정본은 DE편이다.** 새 트랙은 DE편의 사건·숫자·시각을 바꾸지 않는다. DE 시점에서 *보이지 않던 자리와 시간*에서만 이야기를 한다.
- **한 사건, 여러 시점.** 같은 사건을 직군마다 다르게 겪는다. 직군 사이의 오해와 정보 차이가 곧 학습 내용이다.
- **트랙은 독립 완결.** 다른 트랙을 안 해도 이해된다. 교차 장면은 보너스("같은 시각, 다른 자리")다.
- **1차 트랙은 4개**: **지후(PM) — 가장 먼저 제작**, 다온(데이터 분석가), 소라(마케터), 태오(앱 개발자). 후속 후보는 민재(재무), 리아(ML), 석 리드, 윤 대표.
- **PM이 첫 트랙인 이유**: PM은 모든 직군 사이에서 요청을 받고 우선순위를 정하는 *허브*라서, 다른 트랙을 만들 때 교차 지점의 기준이 된다. 비개발 직군 교육(B2B) 수요도 가장 크다고 보고 있다(검증 필요). 자세한 내용은 §7-2.

## 5. 연속성 규칙 (트랙이 지켜야 할 것)

1. **정본 불변.** DE편의 사건·숫자·시각·대사를 바꾸지 않는다. 바꿔야 하면 이 문서에 먼저 기록하고 DE편을 함께 수정한다.
2. **빈틈에서만 이야기한다.** DE편이 화면에 보여 주지 않는 시간(밤, 주말, 회의 전후)과 장소(앱 쪽, 마케팅 쪽, 재무 쪽)가 새 트랙의 무대다.
3. **알고 있는 것만 안다.** 인물은 자기 직군에서 알 수 있는 것만 안다. 이 정보 차이가 갈등과 학습의 원료다. (예: 태오는 필드명이 하류에서 쓰이는 줄 몰랐다.)
4. **교차 장면은 보너스다.** 다른 트랙을 안 한 사람도 이해해야 하므로, 교차 장면에 필수 개념을 넣지 않는다. 교차는 "아, 그때 그 일이 이 사람 눈엔 이랬구나"를 주는 장치다.
5. **한 사건은 한 번만 '결과'를 말한다.** 결과(원인 규명, 해결)는 DE편이 정본이다. 다른 트랙은 같은 결과를 반복하지 않고 *그 사건이 자기 업무에 남긴 것*을 다룬다.
6. **개념의 첫 등장 위치를 존중한다.** DE 바이블 0-9의 "용어 첫 등장 위치"는 DE편 기준이다. 다른 트랙에서 이미 설명된 용어를 쓸 때는 `한글(English, 풀이)`을 한 번 더 쓰되 짧게 쓴다. 각 트랙은 **독립 완결**이어야 하기 때문이다.
7. **새 인물은 최소화한다.** 8명으로 안 풀릴 때만, 트랙당 1명.
8. **현실 주장 금지 유지.** "A/B 테스트는 몇 %가 실패한다" 같은 단정은 쓰지 않는다. 수치는 가상 설정으로만.
9. **성장은 환경과 행동으로.** 외모가 아니라 책상·말투·질문하러 오는 사람 수로 보여 준다(DE 0-3 방식).

## 6. 트랙 구조 공통 틀

| 항목 | 규칙 |
|---|---|
| 길이 | 트랙당 **8장**, 장당 약 3분 → 약 25분 `[초안]` |
| 장 구조 | DE 0-8과 동일: 오프닝 → 문제 → 시도와 실패 → 개념 → 해결 → 한 줄 요약 → 퀴즈 → 성장 |
| 레벨 | 5단계 재사용. 이름만 직군에 맞게 바꾼다(예: 신입 분석가 → … → 시니어 분석가) |
| 역량 축 | 직군별 6축(아래). 장 완료 시 가산 |
| 도감 | 직군별 A–Z 카드 `[초안]`. 직군 간 겹치는 개념은 **같은 글자·같은 정의**, 두 번째 트랙에서 "다른 관점" 문구를 더한다 |
| 인터랙션 | 장당 최대 1개(DE 0-10 계승). 기존 컴포넌트(SQL 실행기, 저울 등)는 최대한 재사용 |
| 교차 카드 | 장 끝에 "같은 시각, 다른 자리" 카드 0~1장. 누르면 해당 트랙·장으로 이동 |
| 메타 게이지 | 트랙을 가로지르는 '바구니 이해도'. 교차 장면 열람과 트랙 완주로 오른다 `[초안]` |

직군별 역량 축 `[초안]`:

- 지후(PM): 문제 정의 / 지표·데이터 / 우선순위 / 실험·검증 / 실행·협업 / 소통·의사결정
- 다온: 쿼리 / 지표 설계 / 시각화·전달 / 실험·통계 / 데이터 의심 / 설득·리딩
- 소라: 지표 이해 / 퍼널·세그먼트 / 실험·귀속 / 데이터 의심 / 도구 활용 / 소통·판단
- 태오: 구현 / 데이터·API 설계 / 성능·확장 / 안정성·운영 / 아키텍처 판단 / 협업·리딩

**시작**: 100명 구간(DE Prologue~Ch1 즈음). **끝**: 1,000만 명, Ch10 이후. 세 트랙 중 **가장 긴 시간선**이라 제작비도 가장 크다.

## 12. 제작 순서 제안

| 순서 | 트랙 | 이유 |
|---|---|---|
| 1 | **지후(PM)** | 요청에 응하는 모든 직군의 허브라서 교차 지점이 가장 많다. 비개발 직군 교육 수요를 가장 직접 겨냥하고, 시스템 다이어그램이 적어 장면 제작비가 낮다. 대신 새 인터랙션 3개와 대사 품질이 비용이다 |
| 2 | 다온(분석가) | 재사용 자산이 가장 많아 비용이 낮고, PM의 P3·P1과 교차한다 |

각 트랙은 **먼저 1~2장(PM이면 P1·P6)만 만들어 반응을 본 뒤** 나머지를 만든다. 지후의 P1은 Ch4의 데이터를 재사용해 가장 싸게 만들 수 있고, P6은 비개발자에게 가장 와닿는 장면이라 반응을 보기에 좋다.

## 13. 결정이 필요한 것

1. 트랙 길이 8장(약 25분)이 맞는가, 짧게(5~6장) 시작할 것인가.
2. 다온 D6 — "일요일 밤에 이상을 발견했지만 아무도 못 봤다"는 설정이 DE Ch7의 "대표가 월요일 08:50에 발견"과 양립한다고 보고 진행해도 되는가. (확인함: Ch7 본문은 "주말 내내 모든 작업이 성공으로 끝났고, 실패 알림은 한 통도 오지 않았다", "사람이 우연히 보기 전까지 틀린 숫자가 그대로 쓰인다"까지만 말하고 아무도 몰랐다고 단정하지는 않는다. 따라서 *사람이 남긴 메모가 묻혔다*는 설정은 정본과 충돌하지 않는다. 다만 Ch7이 "대표가 처음 발견"처럼 읽히지 않게 D6의 표현 수위를 조절해야 한다.)
3. 도감: 직군별 A–Z 26장을 따로 둘 것인가, 공통 도감 하나에 직군 관점 문구를 더할 것인가.
4. 교차 장면의 UX: 장 끝 카드 / 파이프라인 맵 위 아이콘 / 별도 연표 화면 중 무엇인가.
5. 한 사이트 안의 트랙으로 둘 것인가, 직군별 주소로 나눌 것인가(SEO·B2B 영업 측면).
6. ~~첫 트랙을 다온으로~~ → **PM(지후)이 첫 트랙**으로 변경됨(요청에 따라). 이름 '지후'와 "Ch4 회의 직후 채용" 설정을 확정할 것.
7. 새 인물은 지후 1명만 쓴다. PM 트랙에서 더 필요한 인물이 있는가(현재 초안은 없음).
8. P4에서 지후가 "필요한 기간의 끝"을 놓쳐 DE Ch10의 실시간 재고 화면(조회 0회)이 남게 된다는 설정(`[초안]`)을 받아들이는가. 받아들이지 않으면 P4의 포스트잇 복선과 P8 장면 1·2를 정리한다.
9. ~~P6를 Ch7 정본과 맞추기~~ → 확인함. Ch7 스토리보드는 08:50 이후 대표의 행동을 정하지 않았고, 복구 시각(08:58)·수치만 정해져 있어 P6는 그 안에서 쓴다. 남은 확인: Ch7 장면 1 배경에 지후를 한 컷 넣을지(선택).
10. **PM 도감**: DE의 A–Z 26글자는 이미 모두 쓰여 있어, PM 카드 글자(P1의 M·O, P6의 S·C)가 DE 카드와 겹친다. 직군별 별도 도감으로 가면 문제없고, 공통 도감이면 글자 배정 규칙(§6 "같은 글자 같은 정의")과 충돌한다. #3 결정 뒤에 확정한다.
11. **PM 트랙의 시각 기준 장치**: DE편의 파이프라인 맵에 해당하는 것이 PM에게는 없다. 후보: 요청 보드(요청이 쌓이고 정리되는 칸반형), 지표 정의서 모음, 결정 기록. P1·P6는 "맵 변화 없음"으로 썼다.
12. 지후의 말투를 DE와 같은 레벨 말투 체계(Lv1 "일단 해볼게요!" → Lv3 "이렇게 하면 되는데, 이 부분은 조심해야 해요.")로 쓰고 있다. PM만의 말투로 갈지 확인.
13. **다온 트랙의 레벨 체계**: 다온은 Lv1(D1~D2) → Lv2(D3 끝) → Lv3(D6 끝) → Lv4(D7 끝) → Lv5(D8 해결)로 올라 DE편의 승급 위치(Ch2·Ch4·Ch7·Ch10)와 어긋난다. 직군마다 승급 시점이 달라도 되는지, 도감·HUD가 직군별 레벨을 따로 가져가는지 확인.
14. **D6의 일요일 밤 설정**: 다온이 주말에 의심했지만 읽음 0이었다는 설정(`[초안]`)을 받아들이는가. 받아들이지 않으면 D6 장면 1~3을 "월요일 새벽에 알아챔"으로 줄인다.
15. **D5·D3의 통계 설명 수위**: D5는 정규 근사의 단순화한 모델(배지로 고지)을 쓴다. 이 수위로 충분한지, 아니면 계산을 더 줄이고 그림만 남길지.
