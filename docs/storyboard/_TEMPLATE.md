# 챕터 스토리보드 템플릿

각 챕터 파일은 아래 형식을 그대로 따른다. 구현자는 이 파일만 보고 `src/content/chapters/<id>.ts`와 장면 타임라인을 만들 수 있어야 한다.

```markdown
## {Prologue | Ch1 …}. {제목} — {주제}

- 레벨: Lv1 (또는 Lv1→2) / 회사 규모: 사용자 100명 / 분량: 약 3분
- 등장인물: 주니, …
- 획득 카드: S, U
- 맵 변화: + app(쇼핑몰 앱·웹), + csv(CSV 파일) …  (바이블 0-7 그대로)
- 역량 변화: sql +5, design +3, lead +2  (바이블 0-5 그대로)

### 장면 1. 오프닝 (스크롤 연동 아님)
- 화면: 주니의 책상(바이블 0-3 레벨별 환경), 동료 수
- 대사:
  - 윤 대표: "…"
  - 주니(당황): "…"

### 장면 2. 문제 — {장면 제목} [scrub · 3 step]
#### step 1
- 텍스트: (2~3문장, 해요체)
- 대사: (선택, 0~2줄) 주니(집중): "…"
- 화면: (이 step의 정지 상태를 그림처럼 묘사 — 모션 축소 모드에서 그대로 보여줄 그림)
- 모션: (이전 step → 이 step으로 바뀌는 방식. 개념 하나를 설명하는 모션만)
#### step 2
…

### 장면 3. 시도와 실패 — … [scrub · N step]
### 장면 4. 개념 — 비유 … [scrub · N step]
### 장면 5. 개념 — 정의와 쇼핑몰 예시 … [scrub · N step]   (필요하면)
### 장면 6. 해결 — … [scrub · N step]

### 인터랙션: {이름}   (바이블 0-10에 있는 챕터만)
- 위치: 장면 N 다음
- 조작: (버튼·슬라이더·토글 / 키보드 조작)
- 상태별 결과: (상태마다 표·막대·문구가 어떻게 바뀌는지 구체적으로)
- 안내 문구: "…"
- 모션 축소 모드: (애니메이션 없이 결과만 즉시 바뀜 등)

### 한 줄 요약
> (한 문장)

### 퀴즈
- 질문: …
- 보기:
  1. … — ✕ 해설: (왜 틀렸는지 1~2문장)
  2. … — ✓ 해설: (왜 맞는지 1~2문장)
  3. … — ✕ 해설: …
- 공통 해설: (정답을 고른 뒤 모두에게 보여줄 1~2문장)

### 카드 정의
- **S — Schema(스키마)**: (한 줄 사전식 정의, 40~70자)

### 성장 연출
- 카드 획득: …
- 맵 변화: …
- 레벨업: (승급 챕터만) …
- 주니의 한마디: "…"

### 모바일·모션 축소 메모
- …

### 정확성 메모
- (단순화한 곳, 그 이유, 화면에 단순화 고지를 넣은 위치)
```

규칙 요약
- scrub 장면은 장면당 3~4 step (최대 5). 챕터 전체 scrub step 합계 14~20개.
- 텍스트 블록 2~3문장. 한 화면에 개념 하나.
- 각 step의 '화면'은 정지 그림만으로 이해되어야 한다.
- 모든 텍스트는 최종 문구 수준으로 쓴다(초안이라도 플레이스홀더 금지).
